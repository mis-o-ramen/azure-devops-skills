# 報告の書き方 — Azure DevOps での制約

書き方の原則(結論先出し・確証のないことを書かない・本文にコードを引用しない・
空セクションと「該当なし」の使い分け・上限は水増しの許可ではない・二度書かない)の
正典は兄弟スキル `../../output-contract/SKILL.md`(hotl-core のスキル。導入手順に
従って同じ skills ディレクトリに並べて配置する)。**必ずそちらを読む。**
各手順のファイルは、これに加えて固有の上限を定める。

ここに書くのは、投稿先ごとの ADO 固有の制約だけ。

## 投稿先ごとの制約

| 投稿先 | コマンド | 書式 |
| --- | --- | --- |
| プルリクエストのコメント | `pr comment` | Markdown が効く。表・箇条書き・コードブロックを使える |
| 作業アイテムのコメント | `wit comment` | プレーンテキストとして入る。記号はエスケープされ、表は崩れ、折りたたみは使えない |

作業アイテム側に長文を置かない。詳細はプルリクエストに置き、作業アイテムにはリンクと
結論だけ書く。畳めない以上、根拠は省くしかない。
