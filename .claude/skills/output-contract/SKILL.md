# 出力規約

読み手は限られた時間で読み、**次に何をするか**を決める。
この規約は出力の形だけを定める。考える内容を削るためのものではない。

## 前提: 読む時間がボトルネック

AI は放っておくと「網羅的で丁寧なレポート」を書く。丁寧さは善意だが、
読み手にとっては 1 件あたりの所要時間を数倍にする害でしかない。
出力が増えるほど、この害は線形以上に効いてくる。

## 6 つの原則

1. **結論先出し** — 読み手が最初の 3 行で「次に何をすべきか」を決められること。
   結論・判定を先頭に置き、それ以降は判断に必要な情報だけを書く
2. **上限は水増しの許可ではない** — 行数・件数の上限は「そこまで書け」ではない。
   埋めるために内容を薄めない
3. **詳細は折りたたむ** — 調査ログ・データ・コード引用は `<details>` へ。
   ただし**指摘の発生条件と影響は「詳細」ではない**。畳んだり削ったりしない
4. **二度書かない** — diff を読めば分かることを文章で言い換えない。
   同じ内容を二箇所に書かない
5. **空セクションを作らない** — 該当がなければ見出しごと省略する。
   「特になし」も 1 行のコストである。
   **例外はテンプレートが「該当なし」と書くよう求めている欄だけ。**
   そこを省略すると、該当が無かったのか書き忘れたのかを読み手が区別できない。
   区別が要る欄に限ってテンプレート側が明示しているので、勝手に省略しない
6. **密度は件数で買う** — 短いことは目的ではない。読み手が元の資料を
   読み直さないと意味が分からない出力は、1 行でも時間を増やしている。
   1 件あたりを厚くしたいときは、件数の上限を下げて総量を保つ

## 書かないもの

- 前置き、謝辞、依頼文・Issue 本文の再掲、作業手順の実況
- 「まとめ」「所感」「おわりに」（結論の重複は読む量を倍にする）
- 「良い点」（判断に寄与しない）
- 変更ファイルの列挙（差分表示が既に見せている）

## 確証のないことを書かない

画面名・機能名・利用者像・影響は、コード・差分・紐づく Issue から
**確認できたものだけ**を書く。想像で補わない。
断定できないときは条件付きで書くか、その欄ごと省く。

背景や影響を書けと指示されると、AI はもっともらしい作り話で欄を埋めたがる。
埋まっていない欄より、埋まっている誤りのほうが高くつく。

## コードの示し方

- 箇所は `path:line` 形式で示す
- **本文にコードを引用しない。** 場所を指させば読み手は開ける
- どうしても現物が要るときだけ `<details>` に畳み、**5 行以内**に留める
- `<details>` を持てない出力先（チャット応答など）では、引用しない

## 選択肢の示し方

**誰が決めるかで形を変える。**

| 場面 | 形 | 例 |
|---|---|---|
| 正解が一意に決まる（AI が直せる） | 推奨を 1 つ明示する | `推奨 A — 何をするか (理由: 1 句)` / 代案は ` / B: …` |
| 仕様・方針・トレードオフ（人間が決める） | 推奨を付けず、選択肢と帰結を並べる | `A: 案 (帰結) / B: 案 (帰結)` |
| 意見を求められた（設計相談） | 推奨を明示し、各案に帰結を添える | `**推奨 A** — 何をするか (帰結)` |

判断材料を持っていない場面で推奨を出すと、人間の判断を AI が誘導することになる。
逆に、意見を求められて選択肢だけ並べるのは答えていないのと同じ。

どの場面でも**帰結は省かない**。推奨以外を選んだときに何が起きるかが読めないと、
人間は推奨を蹴る判断ができない。

## 足りなかったとき

**詳細は消えていない。** `<details>` を開けば根拠は読める。
それでも足りなければ、聞き直せばそのターンで出す。
**「全員が毎回読む長文」から「必要な人が必要なときに聞く」へ移す**のが狙いであって、
情報を捨てているわけではない。

## 出力前のセルフチェック

- [ ] 最初の 3 行だけで次の行動が決まるか
- [ ] 上限を埋めるために薄めた箇所がないか
- [ ] 該当のないセクションを「特になし」で残していないか
      (テンプレートが「該当なし」を求めている欄は逆に、空のまま残していないか)
- [ ] 同じ内容を二箇所に書いていないか
- [ ] 確認していない画面名・利用者像・影響を書いていないか
- [ ] 本文にコードを引用していないか（`path:line` で足りるか）
- [ ] 選択肢に帰結が付いているか。推奨の有無は「誰が決めるか」と合っているか
- [ ] 「まとめ」「所感」「良い点」を書いていないか
